# Contributing to Sideband

Bug fixes, tests, documentation and new ideas are welcome. For a larger change,
open an issue first so we can agree on the approach.

## Open a pull request

1. Fork the repository to your own GitHub account.
2. In your fork, create a topic branch from the repository's default branch.
3. Make your change and follow the repository's setup and test instructions.
4. Push the branch to your fork. Open a pull request with Sideband's repository
   and its default branch as the base, and your fork and topic branch as the head.
   Use **compare across forks** if GitHub does not show your branch.
5. Explain what changed, why, and how you tested it. Include screenshots for
   visual changes when they help.

You do not need an invitation or write access to Sideband's public repositories
to submit a pull request. If GitHub will not let you create a branch in the
original repository, create it in your fork.

## Review and merge

Pull requests into a repository's default branch require an approving review
from its code owner. Ali Younes, [@whoisaldo](https://github.com/whoisaldo), is the
current maintainer and code owner. New commits dismiss earlier approvals.

The review requirement applies to other administrators too. Only Ali has a
review bypass, so he can merge his own changes while he is the sole maintainer.
All changes to the default branch must still go through a pull request.

Contributions use the license in the repository you are contributing to.
